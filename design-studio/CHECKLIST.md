# เช็กลิสต์ฟีเจอร์เทียบกับ Canva

เอกสารนี้ไล่ดูทุกส่วนของ Canva (ตัวแก้ไข, ข้อความ, รูปภาพ, กราฟิก/อินโฟกราฟิก, เอกสาร, งานนำเสนอ, รายงาน, การส่งออก และหน้าแรก) แล้วตรวจกับ Lai Studio ทีละข้อ

ทุกข้อที่ระบุว่า "ผ่าน" มีชุดทดสอบอัตโนมัติ (`tests/e2e.cjs`) ที่เปิดแอปในเบราว์เซอร์จริง กดใช้งาน และตรวจผล ใช้คำสั่ง `npm test` เพื่อรันซ้ำ

**สัญลักษณ์**

| สัญลักษณ์ | ความหมาย |
|---|---|
| ✅ | มีอยู่แล้วและผ่านการทดสอบ |
| 🆕 | เพิ่มในรอบนี้และผ่านการทดสอบ |
| 🔧 | เจอปัญหาระหว่างตรวจ แก้แล้ว และผ่านการทดสอบซ้ำ |
| ⚠️ | มีบางส่วน (รายละเอียดอยู่ในหมายเหตุ) |
| ❌ | ยังไม่มี แต่ทำได้ในรอบถัดไป |
| ⛔ | ไม่ทำในโปรเจกต์นี้ เพราะเป็นวิดีโอ/AI/ทำงานร่วมกันหลายคน (ตกลงกันไว้แล้ว) หรือต้องมีเซิร์ฟเวอร์และบัญชีผู้ใช้ |

**ผลการทดสอบล่าสุด:**
- ชุดทดสอบหลัก (`tests/e2e.cjs`) ผ่าน **126 / 126 รายการ**
- ชุดทดสอบไฟล์ PowerPoint/Word/PDF (`tests/office.cjs`) ผ่าน **70 / 70 รายการ**
- ชุดทดสอบไฟล์ Word งานเอกสาร/รายงาน (`tests/docs.cjs`) ผ่าน **137 / 137 รายการ** (9 รูปแบบเอกสาร)
- ไม่พบ JavaScript error ตลอดการทดสอบ

### วิธีทดสอบ (`npm run test:office`)

ใช้งานตัวอย่าง 3 ชุด รวม 8 หน้า:
- หน้ารวมทุกองค์ประกอบ
- เอกสาร A4: ใบงาน ประกาศ เกียรติบัตร
- สไลด์ 16:9: หน้าแรก งานสัมมนา โปรโมชัน เมนู

ส่งออกแต่ละชุดเป็น PowerPoint และ Word แล้วเปิดด้วย LibreOffice เพื่อตรวจ 7 เรื่อง:
1. ไฟล์ถูกต้องและจำนวนหน้าตรงกับงาน
2. ข้อความทุกจุดอยู่ในไฟล์เป็นข้อความจริงที่แก้ไขได้
3. ข้อความที่แสดงผลจริงครบ ไม่มีอักขระเสียหรือภาษาแปลก ๆ
4. ไฟล์อ้างถึงฟอนต์ตามงานออกแบบ
5. ตอนแสดงผลใช้ฟอนต์นั้นจริง ไม่ถูกแทนที่
6. ตาราง/กราฟเป็นวัตถุจริง จำนวนครบ
7. เทียบภาพทีละหน้ากับต้นฉบับ (เกณฑ์: ค่าต่างเฉลี่ย < 8 จาก 255 และพิกเซลที่ต่างชัด < 6%)

ผลล่าสุด: ทุกหน้ามีค่าต่างเฉลี่ย **1.7–6.5** (ยกเว้นพื้นที่กราฟ ซึ่งวัดแยกและผ่านเกณฑ์ของกราฟ)

### ทดสอบไฟล์ Word ของงานเอกสาร / รายงาน (`npm run test:docs`)

สร้างรายงาน 3 หน้าในแอป (หน้าปก, บทที่ 1 มีหัวข้อ หัวข้อย่อย ตัวหนา ตัวสี รายการ, บทที่ 2 มีตาราง) ใน 9 รูปแบบ:

| แบบ | การตั้งค่า |
|---|---|
| ธรรมดา | ไม่มีเลขหน้า ไม่มีลายน้ำ ไม่มีหัว/ท้ายกระดาษ |
| เลขหน้า | ท้ายกระดาษ กึ่งกลาง แบบ "1" |
| มีหน้าปก | หัวกระดาษชิดซ้าย + เลขหน้า "หน้า 1 จาก 3" ชิดขวาบนหัวกระดาษ ไม่แสดงในหน้าปก |
| ลายน้ำ | "ร่าง" แนวทแยง ไม่มีเลขหน้า |
| เอกสารลับ | หัวกระดาษ "ลับ" ตัวหนาสีแดง ท้ายกระดาษตัวหนาสีแดง เลขหน้า "- 1 -" ลายน้ำ "ลับมาก" ขอบเส้นเดี่ยวสีแดง |
| ครบทุกอย่าง (A4 แนวนอน) | หัวกระดาษตัวเอียงสีน้ำเงิน ท้ายกระดาษชิดขวา เลขหน้า "1 / 3" ลายน้ำ DRAFT แนวนอน ขอบเส้นคู่ และเลขหน้าที่วางเองบนหน้า |
| ขอบเส้นจุด / เส้นหนา / เส้นประ | ร่วมกับหัวกระดาษชิดขวา, เลขหน้า "หน้า 1" ชิดซ้าย, ท้ายกระดาษ 2 บรรทัด |

แต่ละแบบส่งออกเป็น Word แล้วตรวจ 4 ส่วน:
1. **โครงสร้างไฟล์ Word:**
   - หัว/ท้ายกระดาษเป็นของ Word จริง ข้อความ ตัวหนา ตัวเอียง และสีถูกต้อง
   - เลขหน้าเป็นฟิลด์ PAGE/NUMPAGES และตั้งค่าไม่แสดงในหน้าแรกได้ถูก
   - ลายน้ำเป็นลายน้ำของ Word และขอบกระดาษถูกแบบ
   - หัวข้อเป็น Heading 1/2 และตัวหนา/ตัวสีเป็นรูปแบบของข้อความจริง
   - แบบที่ไม่ได้ใส่จะต้องไม่มีสิ่งเหล่านี้
2. **เปิดด้วย LibreOffice:**
   - จำนวนหน้าและขนาดกระดาษตรง
   - ข้อความในแถบหัว/ท้ายกระดาษของทุกหน้าตรงกับที่ควรเป็น (รวมเลขหน้าแต่ละหน้า) ทั้งในไฟล์ Word และ PDF ต้นฉบับ
   - เนื้อหาครบไม่เพี้ยน ลายน้ำและขอบกระดาษมองเห็นทุกหน้า (ตรวจจากสีพิกเซล)
   - หน้าตาเหมือนต้นฉบับ: ค่าต่างเฉลี่ย 0–7.9 จาก 255 (เกณฑ์ < 8) ต่างที่ขอบเส้นหนาและการตัดคำมากที่สุด
3. **แก้ไขได้:** ใช้ python-docx (ไลบรารีแก้ไฟล์ Word) ทำสิ่งต่อไปนี้ แล้วเปิดดูผล:
   - แก้หัว/ท้ายกระดาษ แก้หัวข้อ แก้ช่องตาราง ทำตัวหนา และเพิ่มหน้าใหม่ที่มีย่อหน้าใหม่
   - ผล: เห็นการแก้ครบ ได้ 4 หน้า และเลขหน้าเปลี่ยนเป็น "จาก 4" เอง
4. **เปิดแล้วบันทึกซ้ำด้วย LibreOffice:** หัว/ท้ายกระดาษ ฟิลด์เลขหน้า และลายน้ำยังอยู่ครบ

**ข้อจำกัดที่ควรรู้**
- **ลายน้ำใน Word อยู่หลังข้อความ:** Word วางลายน้ำไว้หลังเนื้อหาเสมอ ถ้ามีตารางหรือรูปทึบตรงกลางหน้า ลายน้ำจะถูกบังส่วนนั้น ส่วนในแอปและ PDF ลายน้ำอยู่บนสุดแบบโปร่งใส และ LibreOffice วาดลายน้ำด้วยตัวอักษรบางกว่าใน Word
- **ข้อความที่พิมพ์เพิ่มใน Word:** เนื้อหาเดิมถูกวางตำแหน่งตายตัวตามงานออกแบบ ข้อความใหม่ที่พิมพ์ใน Word จึงเริ่มที่ขอบบนของหน้า (ภายในระยะขอบ) และไม่ดันเนื้อหาเดิมลง เหมาะกับการเพิ่มหน้าใหม่ หรือแก้ข้อความที่มีอยู่ ถ้าแก้ข้อความให้ยาวขึ้นจนขึ้นบรรทัดใหม่ บรรทัดใหม่จะอยู่ในกรอบเดิมและอาจทับข้อความถัดไป (ต้องเลื่อนกรอบเอง) ข้อความใหม่ใช้ Sarabun 16 pt เป็นค่าเริ่มต้น
- **ต้องมีฟอนต์ในเครื่อง:** เครื่องที่เปิดไฟล์ต้องติดตั้งฟอนต์ที่ใช้ในงาน (Google Fonts ฟรีทั้งหมด) ไม่เช่นนั้นโปรแกรมจะใช้ฟอนต์อื่นแทน ข้อความยังครบแต่หน้าตาจะเปลี่ยน
- **หน้าตากราฟ:** กราฟถูกส่งออกเป็นกราฟจริงที่แก้ข้อมูลได้ PowerPoint/Word จึงวาดเส้นแกนและขนาดป้ายตัวเลขตามแบบของตัวเอง
- **ทดสอบด้วย LibreOffice เท่านั้น:** ยังไม่ได้เปิดทดสอบใน Microsoft Office จริง
- **การซ้อนตารางใน Word บน LibreOffice:** LibreOffice วาดตารางลอยใน Word ไว้บนภาพที่วางทับเสมอ ถ้าในงานมีภาพทับตาราง ลำดับการซ้อนอาจกลับกันเมื่อเปิดด้วย LibreOffice

## สรุปปัญหาที่พบระหว่างตรวจและแก้แล้ว

ทุกข้อแก้แล้ว และรันชุดทดสอบทั้งหมดซ้ำหลังแก้แต่ละข้อ เพื่อยืนยันว่าส่วนอื่นยังทำงานปกติ

| # | ปัญหา | ผลกระทบต่อผู้ใช้ | วิธีแก้ |

| 2 | ลิงก์ภาษาไทยใน PDF ไม่เป็นรูปแบบมาตรฐาน | บางโปรแกรมเปิดลิงก์ใน PDF ไม่ได้ | แปลงเป็น percent-encoding ก่อนบันทึก |
| 3 | การจัดตารางใหม่หลัง "แทนที่ทั้งหมด" เพิ่มขั้นเลิกทำเกินมา | ต้องกดเลิกทำ 2 ครั้ง | ปรับประวัติการเลิกทำในที่เดิม ไม่เพิ่มขั้นใหม่ |
| 4 | การใส่เลขหน้ากินขั้นเลิกทำ 2 ขั้น | ต้องกดเลิกทำ 2 ครั้ง | จัดตำแหน่งก่อนเพิ่มลงงาน ให้เป็นขั้นเดียว |

| 9 | ไม้บรรทัดกว้างแค่ 40px และตัวเลขวาดผิดแกน | ใช้ไม้บรรทัดไม่ได้ | กำหนดขนาด canvas ของไม้บรรทัดให้ถูก และแยกแกนให้ถูก |
| 10 | Word: ข้อความทุกจุดกลายเป็นภาพ | แก้ข้อความใน Word ไม่ได้ | ไม่นับค่าเส้นขอบเริ่มต้นของ Fabric (1px แต่ไม่มีสี) เป็นเส้นขอบจริง |
| 11 | สีเฉพาะคำคลาดตำแหน่งใน PowerPoint/Word | คำผิดถูกทำสี | นับตำแหน่งตามกลุ่มอักขระ (grapheme) แบบเดียวกับตัวแก้ไข เช่น "ตั้" นับเป็น 1 ตำแหน่ง |
